ESP32-C5 · Secure Boot v2 · ESP-IDF v6.0.1

Command quick reference

Every command to take one board from unprotected to locked. Port COM15; run from the project folder.

reversible irreversible · burns eFuses $ command / prompt eFuse name
⚙

Setup & everyday

One-time target + the loop you’ll repeat.

$ idf.py set-target esp32c5
$ idf.py build
$ idf.py -p COM15 flash monitor # exit: Ctrl-]
$ idf.py fullclean # after editing sdkconfig.defaults
$ idf.py -p COM15 efuse-summary # what's burned
1

Baseline

reversible

Build + flash as-is → confirm Secure Boot: DISABLED.

$ idf.py build && idf.py -p COM15 flash monitor

Expect Secure Boot v2 : DISABLED — nothing burned.

2

Sign the app

reversible

Real signature, no eFuse burn. Software only.

Generate signing key

$ idf.py secure-generate-signing-key \ --scheme ecdsa256 secure_boot_signing_key.pem

sdkconfig keys

CONFIG_SECURE_SIGNED_APPS_NO_SECURE_BOOT=y CONFIG_SECURE_SIGNED_APPS_ECDSA_V2_SCHEME=y CONFIG_SECURE_BOOT_ECDSA_KEY_LEN_256_BITS=y CONFIG_SECURE_BOOT_SIGNING_KEY="secure_boot_signing_key.pem"

Rebuild & inspect

$ idf.py fullclean && idf.py build
$ espsecure signature-info-v2 build/secure_boot_demo.bin

Still reports DISABLED — signing ≠ locking.

3

Lock — IDF flow

irreversible

Recommended path. Spare board only.

1 · configure

$ idf.py menuconfig # Security features → Enable hardware Secure Boot

2 · build + flash bootloader by hand

$ idf.py bootloader # prints the write-flash cmd
$ esptool --chip esp32c5 -p COM15 -b 460800 \ write-flash 0x2000 build/bootloader/bootloader.bin

3 · flash app, first boot burns eFuses

$ idf.py -p COM15 flash monitor # NOT the bootloader

Expect Secure Boot v2 : ENABLED, then verify with efuse-summary.

3

Lock — manual (espefuse)

irreversible

Explicit burn, e.g. for external provisioning. Order matters.

$ espsecure generate-signing-key --version 2 \ --scheme ecdsa256 secure_boot_signing_key.pem
$ espsecure digest-sbv2-public-key \ --keyfile secure_boot_signing_key.pem --output digest.bin
$ espefuse --port COM15 --chip esp32c5 \ burn-key BLOCK_KEY0 digest.bin SECURE_BOOT_DIGEST0
$ espefuse --port COM15 --chip esp32c5 \ burn-efuse SECURE_BOOT_EN

P-384? also burn SECURE_BOOT_SHA384_EN. Harden: DIS_PAD_JTAG, DIS_USB_JTAG.

4

Encrypt flash

irreversible

Confidentiality. Enable with Stage 3. AES-XTS key locked in eFuse.

$ idf.py menuconfig # Enable flash encryption → mode Development/Release
$ idf.py -p COM15 flash monitor # first boot encrypts in place

re-flash later

$ idf.py -p COM15 encrypted-flash monitor # DEV mode only

Release mode: updates are OTA-only. Never cut power mid-encryption.

!

Recovery

“Bricked” = usually can’t-update, not dead.

$ idf.py -p COM15 encrypted-flash monitor # dev-mode plaintext soft-brick

Recoverable: wrong-key app (re-flash signed) · plaintext-on-encrypted in dev mode · power-loss mid-encrypt.

Unrecoverable: lost signing key · download mode permanently disabled + bad image. Back up *.pem offline.
